# 데이터 모델 — Firestore 구조

이 문서는 가위바위보 챌린지 이벤트의 Firestore 데이터 구조를 정리합니다. 컬렉션·문서 계층, 각 필드의 의미, 문서 간 관계, 데이터 라이프사이클을 한 곳에 모았습니다.

---

## 1. 컬렉션 트리

```
events/
└── active/                                  ← 단일 이벤트 문서 (문서 ID 고정: 'active')
    ├── (이벤트 상태 필드들)
    │
    ├── players/                             ← 참여자 서브컬렉션
    │   ├── {externalUserId_1}/              ← 문서 ID = 자사 uid
    │   ├── {externalUserId_2}/
    │   └── ...
    │
    └── rounds/                              ← 라운드별 결과 서브컬렉션
        ├── 1/                               ← 문서 ID = 라운드 번호
        ├── 2/
        └── ...
```

**핵심 설계 원칙**:
- **단일 이벤트**: 동시에 한 게임만 운영하므로 `events/active` 하나로 고정
- **자사 uid = 문서 ID**: 같은 사용자가 다시 호출해도 동일 문서를 자연스럽게 찾기 위함 (재진입 차단 정책의 기반)
- **라운드 번호 = 문서 ID**: 라운드별 결과를 시계열로 정렬·조회 가능

---

## 2. `events/active` — 이벤트 상태 (단일 문서)

게임 전체의 현재 상태를 담는 단일 문서. 모든 클라이언트가 onSnapshot 으로 실시간 구독.

| 필드 | 타입 | 의미 | 변경 주체 |
|---|---|---|---|
| `phase` | `'pending'` \| `'registration'` \| `'countdown'` \| `'select'` \| `'reveal'` \| `'ended'` | 현재 게임 페이즈 | tick 함수 (자동) |
| `currentRound` | `number` | 현재 진행 중인 라운드 번호. `0` = 게임 시작 전, `1+` = 라운드 진행 중 | tick |
| `aiChoice` | `'rock'` \| `'paper'` \| `'scissors'` \| `null` | 현재 라운드의 컴퓨터 손. select 페이즈까지는 `null`, reveal 시 결정·기록 | tick (select→reveal 시) |
| `aliveCount` | `number` | 현재 살아있는 참가자 수 (라운드 종료 후 갱신) | tick |
| `winnerId` | `string` \| `null` | 우승자의 자사 uid (= externalUserId). 게임 종료 시 채워짐 | tick (reveal→ended 시) |
| `registrationOpensAt` | `Timestamp` | **입장 가능 시작 시각** — 운영자가 사전 설정 | 운영자 (Firebase 콘솔) |
| `startsAt` | `Timestamp` | **게임 자동 시작 시각** — 운영자가 사전 설정 | 운영자 |
| `phaseEndsAt` | `Timestamp` \| `null` | 현재 페이즈가 끝나는 시각. tick 이 시각 도달 시 다음 페이즈로 전환 | tick |
| `countdownDurationMs` | `number` | 라운드 시작 카운트다운 길이 (밀리초). 예: `5000` = 5초 | 운영자 |
| `selectDurationMs` | `number` | 손 선택 시간 길이 (밀리초). 예: `5000` | 운영자 |
| `revealDurationMs` | `number` | 결과 노출 시간 길이 (밀리초). 예: `3000` | 운영자 |
| `maxRounds` | `number` | 최대 라운드 수. 도달 시 winner 미정이라도 ended | 운영자 |
| `capacity` | `number` | 정원 (참고용 — 현재 MVP 는 정원 게이트 미구현) | 운영자 |
| `endReason` | `'winner'` \| `'all_eliminated'` \| `'max_rounds_reached'` \| `'no_players'` \| `null` | 게임 종료 사유 | tick |

### 페이즈 전이 흐름

```
pending → registration → countdown ⇄ select ⇄ reveal → ended
              │              ↑                    │
              └─ tick 자동 ──┘                    └─ winner / 이월
```

- `pending` → `registration`: `registrationOpensAt` 도달 시. 이전 게임 데이터 자동 정리.
- `registration` → `countdown`: `startsAt` 도달 시. alive count 측정 후 라운드 1 시작.
- `countdown` ↔ `select` ↔ `reveal`: `phaseEndsAt` 기준 자동 전환. reveal 종료 시 다음 라운드 또는 ended 분기.

## 3. `events/active/players/{externalUserId}` — 참여자 (서브컬렉션)

각 참여자의 상태. **문서 ID 가 자사 uid (externalUserId)** 라 같은 사용자의 재진입을 자연스럽게 감지.

| 필드 | 타입 | 의미 | 변경 주체 |
|---|---|---|---|
| `externalUserId` | `string` | 자사 uid (= 문서 ID 와 동일) | joinEvent (생성 시) |
| `clickKey` | `string` | 광고 클릭 식별자. 적립 시 어드민 시스템에서 검증용 | joinEvent |
| `currentFirebaseUid` | `string` | 이 사용자의 Firebase 익명 UID. 보안 규칙 본인 검증용 (`request.auth.uid == currentFirebaseUid`) | joinEvent (생성 시 1회만) |
| `alive` | `boolean` | 생존 여부. 라운드 진행 중 false 가 되면 탈락 (관전 모드) | tick (일괄 판정), joinEvent (재진입 탈락) |
| `lastChoice` | `'rock'` \| `'paper'` \| `'scissors'` \| `null` | 가장 최근 선택한 손 | 클라이언트 (select 페이즈에서만) |
| `lastChoiceRound` | `number` | 위 lastChoice 가 어느 라운드 선택인지. 라운드 번호와 일치해야 유효 | 클라이언트 |
| `eliminatedRound` | `number` \| `null` | 탈락된 라운드 번호 | tick / joinEvent |
| `eliminationReason` | `'lose'` \| `'tie'` \| `'no_choice'` \| `'rejoin'` \| `null` | 탈락 사유 | tick / joinEvent |
| `joinedAt` | `Timestamp` | 등록 시각 (서버 시각) | joinEvent (FieldValue.serverTimestamp) |

### `eliminationReason` 의미

| 값 | 발생 시점 |
|---|---|
| `'lose'` | 컴퓨터 손에 졌을 때 (예: rock vs paper → lose) |
| `'tie'` | 컴퓨터 손과 비겼을 때 |
| `'no_choice'` | 시간 안에 손을 안 냈을 때 |
| `'rejoin'` | 게임 진행 중 다시 들어와서 자동 탈락된 경우 |

## 4. `events/active/rounds/{roundNumber}` — 라운드 결과 (서브컬렉션)

각 라운드의 결과 통계 스냅샷. select → reveal 전환 시 1회 작성. 모든 클라이언트가 라운드 통계 화면에 사용.

| 필드 | 타입 | 의미 |
|---|---|---|
| `aiChoice` | `'rock'` \| `'paper'` \| `'scissors'` | 이 라운드 컴퓨터 손 |
| `revealedAt` | `Timestamp` | 결과 공개된 시각 (서버 시각) |
| `survivorsBefore` | `number` | 라운드 시작 시 생존자 수 |
| `survivorsAfter` | `number` | 라운드 종료 후 생존자 수 |
| `eliminatedCount` | `number` | 이 라운드에서 탈락한 인원 = `survivorsBefore - survivorsAfter` |
| `rockCount` | `number` | 바위(rock) 를 낸 사용자 수 |
| `paperCount` | `number` | 보(paper) 를 낸 사용자 수 |
| `scissorsCount` | `number` | 가위(scissors) 를 낸 사용자 수 |
| `noChoiceCount` | `number` | 손을 못 낸 사용자 수 (시간 초과 등) |

> 생존율 = `survivorsAfter / survivorsBefore`. 이 값으로 "1만명 중 3,300명 진출 (33%)" 같은 통계 표시.

## 5. 문서 간 관계

```
                ┌─────────────────────────────┐
                │  events/active              │
                │  (이벤트 전역 상태, 단일 문서) │
                └──┬───────────────────┬──────┘
                   │                   │
        ┌──────────▼───────┐   ┌───────▼────────┐
        │  players/        │   │  rounds/       │
        │  서브컬렉션      │   │  서브컬렉션    │
        │  N개 (참여자별)  │   │  N개 (라운드별) │
        └──────────────────┘   └────────────────┘
```

| 관계 | 카디널리티 | 키 |
|---|---|---|
| events/active ↔ players/{externalUserId} | 1:N | externalUserId (자사 uid) |
| events/active ↔ rounds/{roundNumber} | 1:N | roundNumber (1, 2, 3, ...) |
| players ↔ rounds | (직접 관계 없음) | 라운드 통계는 집계로 산출, 개별 사용자의 손은 players.lastChoice 에서 |

### 같은 사용자 식별의 두 가지 키

| 키 | 용도 | 변경 가능성 |
|---|---|---|
| `externalUserId` (자사 uid) | 비즈니스 식별자. 운영자가 winnerId 보고 어드민에서 적립할 때 사용 | 불변 (게임 전체에 걸쳐 고정) |
| `currentFirebaseUid` (익명 Firebase UID) | Firebase 보안 규칙 본인 검증용 (`request.auth.uid` 매칭) | 첫 등록 시점에 fix. 재진입은 차단되므로 변경 불필요 |

## 6. 데이터 라이프사이클

```
[이전 게임 ended 상태]
       │
       │ 운영자가 phase='pending' + 시각 갱신
       ▼
[pending 페이즈]
       │ tick: registrationOpensAt 도달
       │   ├─ players 컬렉션 전체 삭제
       │   ├─ rounds 컬렉션 전체 삭제
       │   └─ events/active 의 게임 상태 필드 초기화
       │      (currentRound=0, aliveCount=0, aiChoice=null, winnerId=null, endReason=null)
       ▼
[registration 페이즈]
       │ 사용자가 joinEvent 호출 → players/{externalUserId} 생성
       │ tick: startsAt 도달
       │   └─ alive count 측정, currentRound=1, aliveCount=N
       ▼
[countdown → select → reveal] 라운드 N회 반복
       │ select → reveal 시:
       │   ├─ tick: 컴퓨터 손 결정, 일괄 판정
       │   ├─ players/{...}.alive 갱신 (탈락자)
       │   └─ rounds/{N} 통계 문서 생성
       │ reveal → 다음 countdown 또는 ended
       ▼
[ended 페이즈]
       │ winnerId 자동 기록 (자사 uid)
       │ phaseEndsAt = null
       └─ 운영자가 다음 회차 위해 phase='pending' 으로 변경 → 처음으로 돌아감
```

## 7. 보안 규칙 요약 (`firestore.rules`)

| 컬렉션·문서 | 클라이언트 read | 클라이언트 write |
|---|---|---|
| `events/{eid}` | ✅ 인증 사용자 (모두 같은 게임 상태 공유) | ❌ 금지 (Cloud Functions 만) |
| `events/{eid}/rounds/{N}` | ✅ 인증 사용자 (라운드 통계는 모두 봄) | ❌ 금지 (Cloud Functions 만) |
| `events/{eid}/players/{externalUserId}` | ✅ **본인만** (`request.auth.uid == currentFirebaseUid`) | ❌ create 금지 (joinEvent 만), update 는 본인의 lastChoice 만 select 페이즈에서 가능 |

### update 시 검증되는 immutable 필드 (변경 불가)

`players/{uid}` 의 update 는 보안 규칙이 다음 필드를 변경 불가로 락:
- `externalUserId`, `clickKey`, `currentFirebaseUid`, `alive`, `joinedAt`, `eliminatedRound`, `eliminationReason`

→ 클라이언트는 본인의 `lastChoice` 와 `lastChoiceRound` 만 select 페이즈에서 변경 가능.

## 8. 빠른 조회 시나리오별 참조

| 운영자가 알고 싶은 것 | 어디 보면 되나 |
|---|---|
| 현재 게임 진행 단계 | `events/active.phase` |
| 우승자 자사 uid | `events/active.winnerId` |
| 우승자 clickKey (적립용) | `events/active/players/{winnerId}.clickKey` |
| 라운드별 생존자 변화 | `events/active/rounds/*.survivorsAfter` |
| 라운드별 컴퓨터 손 | `events/active/rounds/*.aiChoice` |
| 어떤 라운드에서 사용자가 탈락했는지 | `events/active/players/{uid}.eliminatedRound` + `eliminationReason` |
| 부정행위 의심 패턴 (재진입 탈락) | `players/*.eliminationReason == 'rejoin'` 인 사용자 목록 |
