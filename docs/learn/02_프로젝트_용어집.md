# 2. 프로젝트 용어집

이 문서는 기존 guide/task/flow 문서에 자주 나오는 단어를 쉬운 말로 정리한다.

## Firebase 서비스 용어

| 용어 | 쉬운 뜻 | 이 프로젝트에서 보면 되는 포인트 |
|---|---|---|
| Firebase | Google의 앱 개발 도구 묶음 | Hosting, Auth, Firestore, Functions 등을 함께 쓴다. |
| Firebase Hosting | 웹 파일을 배포하는 서비스 | React 앱을 CDN으로 서빙한다. |
| CDN | 가까운 서버에서 파일을 빠르게 주는 네트워크 | 사용자가 `index.html`, JS 파일을 빠르게 받는다. |
| SPA | 한 개 HTML에서 화면을 바꾸는 웹앱 | `/event`도 결국 `index.html`로 들어와 React가 처리한다. |
| rewrite | URL을 내부 파일로 연결하는 규칙 | `/event?...` 요청을 `/index.html`로 보낸다. |
| Firebase Authentication | 사용자를 인증하는 서비스 | Anonymous Auth로 임시 사용자 ID를 만든다. |
| Anonymous Auth | 회원가입 없는 익명 로그인 | 사용자의 Firebase Auth UID를 만든다. |
| Firebase Auth UID | Firebase가 발급한 내부 사용자 ID | 문서에서는 보통 `userId`로 부른다. URL `uid`와 다르다. |
| Firestore | 문서형 데이터베이스 | 게임 상태, 플레이어 상태, 라운드 결과를 저장한다. |
| Cloud Functions | 서버 함수를 실행하는 서비스 | 입장, 선택, 라운드 종료, 우승자 정보 제출을 처리한다. |
| Cloud Tasks | 예약된 HTTP 작업을 실행하는 큐 | `beginSelect`, `endRound`를 정해진 시각에 호출한다. |
| Pub/Sub | 메시지를 발행하고 구독자에게 전달하는 서비스 | 대량 판정을 batch 단위로 나눠 `processBatch`에 보낸다. |
| Emulator | 로컬에서 Firebase처럼 돌리는 테스트 도구 | 실제 배포 전 보안 규칙과 함수를 검증한다. |

## Firestore 데이터 용어

| 용어 | 쉬운 뜻 | 예시 |
|---|---|---|
| collection | 문서들을 담는 폴더 | `games`, `players`, `rounds` |
| document | 실제 데이터를 담는 파일 | `games/{gameId}` |
| subcollection | 문서 아래에 있는 하위 폴더 | `games/{gameId}/players/{userId}` |
| field | 문서 안의 값 | `phase`, `aliveCount`, `winnerNickname` |
| document ID | 문서 이름 | `players/{userId}`의 `userId` 부분 |
| security rules | 클라이언트가 읽고 쓸 수 있는 범위 규칙 | 본인 player만 읽게 제한한다. |
| index | 빠른 조회를 위한 색인 | 특정 query가 필요할 때 만든다. |
| transaction | 여러 읽기/쓰기를 한 번에 안전하게 처리 | 입장 시 claims, player, counter를 함께 갱신한다. |
| batch write | 여러 쓰기를 묶어 처리 | 대량 판정의 일부 처리에 사용될 수 있다. |
| shard counter | 카운터를 여러 문서로 나눠 쓰는 방식 | 1만 명 입장/탈락에서 단일 카운터 병목을 줄인다. |

## Cloud Functions 용어

| 용어 | 쉬운 뜻 | 이 프로젝트 예시 |
|---|---|---|
| Callable Function | 앱에서 직접 호출하는 서버 함수 | `joinGame`, `submitChoice`, `submitWinnerInfo` |
| HTTP Function | HTTP 요청으로 호출되는 서버 함수 | Cloud Tasks가 `beginSelect`, `endRound`를 호출한다. |
| trigger | 어떤 사건이 함수를 실행하게 하는 것 | Pub/Sub 메시지가 `processBatch`를 실행한다. |
| region | 함수가 배치되는 지역 | 문서에서는 `asia-northeast3`를 기준으로 한다. |
| runtime | 함수가 실행되는 Node.js 환경 | Functions 코드가 실행되는 기반이다. |
| request.auth.uid | Callable 요청자의 Firebase Auth UID | 서버가 “누가 호출했는지” 확인하는 값이다. |
| error code | 실패 이유를 나타내는 코드 | `unauthenticated`, `failed-precondition`, `already-exists` 등 |

## Cloud Tasks / Pub/Sub 용어

| 용어 | 쉬운 뜻 | 이 프로젝트 예시 |
|---|---|---|
| queue | 실행할 작업을 줄 세우는 곳 | `game-rounds` 큐 |
| task | 큐에 들어가는 작업 1개 | `beginSelect` 호출 작업, `endRound` 호출 작업 |
| schedule time | 작업을 실행할 시각 | 선택 시작 시각, 선택 마감 시각 |
| deterministic task name | 같은 상황이면 항상 같은 task 이름 | 중복 예약을 자연스럽게 막는다. |
| `ALREADY_EXISTS` | 이미 같은 이름의 작업이 있다는 뜻 | 같은 task를 두 번 만들 때 두 번째가 실패한다. |
| topic | Pub/Sub 메시지를 보내는 채널 | `process-batch` |
| message | Pub/Sub로 전달되는 작업 내용 | `{ gameId, roundNumber, batchIndex }` |
| dead-letter | 계속 실패한 메시지를 따로 보내는 곳 | 운영에서 실패 원인을 추적할 때 쓴다. |

## 보안 / 운영 용어

| 용어 | 쉬운 뜻 | 이 프로젝트에서 보면 되는 포인트 |
|---|---|---|
| IAM | Google Cloud 리소스 권한 관리 | 어떤 service account가 어떤 함수를 호출할 수 있는지 정한다. |
| service account | 서버끼리 사용하는 계정 | Cloud Tasks가 함수 호출할 때 사용한다. |
| OIDC | 서버 간 호출 신분증 토큰 방식 | Cloud Tasks 호출이 진짜인지 함수가 확인한다. |
| audience | OIDC 토큰이 향하는 대상 | 다른 함수/환경 URL 토큰이면 거부한다. |
| Secret Manager | 비밀값 저장소 | service account key나 secret을 코드에 두지 않는다. |
| Cloud Logging | 로그 저장/검색 | 함수 호출 오류와 batch 상태를 추적한다. |
| Cloud Monitoring | 지표와 알림 | 큐 길이, 실패율, batch 상태를 대시보드로 본다. |
| alert | 이상 상황 알림 | prd 5xx나 batch failed를 운영 채널로 보낸다. |

## 게임 도메인 용어

| 용어 | 쉬운 뜻 | 설명 |
|---|---|---|
| `phase` | 게임의 현재 단계 | `waiting`, `countdown`, `select`, `reveal`, `ended` |
| `waiting` | 입장 대기 | 첫 라운드 시작 전 입장을 받는 단계 |
| `countdown` | 선택 전 카운트다운 | 곧 선택이 시작됨을 보여주는 단계 |
| `select` | 선택 단계 | 사용자가 가위/바위/보를 제출한다. |
| `reveal` | 결과 공개 단계 | 애디슨 손과 판정 결과를 보여준다. |
| `ended` | 종료 | 우승 또는 이월로 게임이 끝난 상태 |
| `adisonUid` | URL `uid`를 문서에서 부르는 이름 | Firebase Auth UID와 구분하기 위한 이름이다. |
| `clickKey` | 지급 확인용 외부 키 | 중복 참여 차단 키로 쓰지 않는다. |
| `claims` | 입장 선점 기록 | 같은 Adison 사용자의 중복 참여를 막는다. |
| `adminChoice` | 애디슨의 가위/바위/보 | `reveal` 전에는 공개되면 안 된다. |
| `aliveCount` | 현재 생존자 수 | 다음 라운드 또는 종료 분기에 사용한다. |
| `winnerPrivate` | 우승자 비공개 지급 정보 영역 | 개인정보는 공개 문서에 두지 않는다. |

## 처리 방식 용어

| 용어 | 쉬운 뜻 | 왜 필요한가 |
|---|---|---|
| idempotent / 멱등 | 여러 번 실행해도 결과가 한 번 실행한 것과 같음 | Cloud Tasks/Pub/Sub 재시도 때문에 필요하다. |
| guard / 가드 | 실행해도 되는지 먼저 확인하는 조건 | 잘못된 phase에서 중복 처리하지 않게 막는다. |
| fan-out | 한 번의 변경이 많은 읽기/알림으로 퍼지는 현상 | 공통 문서 실시간 구독을 줄이는 이유다. |
| polling | 주기적으로 다시 읽기 | 공통 상태를 5초 내외로 읽는다. |
| onSnapshot | Firestore 실시간 구독 | 본인 player 상태에 사용한다. |
| batch manifest | 처리할 batch 목록을 미리 고정한 기록 | 중간 실패 후 재시도해도 같은 범위를 처리한다. |
| finalizer | 마지막 정리 처리 | 모든 batch가 끝난 뒤 다음 라운드/종료를 결정한다. |
