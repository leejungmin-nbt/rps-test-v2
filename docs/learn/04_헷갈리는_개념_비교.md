# 4. 헷갈리는 개념 비교

비슷해 보이지만 역할이 다른 단어들을 비교한다.

## Firebase Auth UID vs URL `uid`

| 구분 | Firebase Auth UID | URL `uid` / `adisonUid` |
|---|---|---|
| 누가 만드나 | Firebase Authentication | Adison/NBT 쪽 진입 URL |
| 문서 내 이름 | `userId` | `adisonUid` |
| 용도 | 현재 요청자가 누구인지 확인 | 같은 외부 사용자의 중복 참여 차단 |
| 바뀔 수 있나 | 브라우저 상태 초기화/다른 기기에서 바뀔 수 있음 | 매체 사용자 기준으로 유지된다고 가정 |
| 주의 | 중복 참여 차단의 유일 기준으로 쓰지 않는다 | Firebase Auth UID와 이름을 섞지 않는다 |

## Callable Function vs HTTP Function

| 구분 | Callable Function | HTTP Function |
|---|---|---|
| 누가 호출하나 | React 앱 | Cloud Tasks 같은 서버 작업자 |
| 인증 확인 | `request.auth.uid`를 쉽게 쓴다 | OIDC 등 별도 검증이 필요하다 |
| 예시 | `joinGame`, `submitChoice`, `submitWinnerInfo` | `beginSelect`, `endRound` |
| 쉬운 비유 | 앱에서 누르는 버튼 API | 서버끼리 부르는 내부 endpoint |

## Cloud Tasks vs Pub/Sub

| 구분 | Cloud Tasks | Pub/Sub |
|---|---|---|
| 핵심 역할 | 정해진 시간 또는 큐 순서대로 HTTP 호출 | 메시지를 여러 작업자에게 전달 |
| 이 프로젝트 예시 | 선택 시작/마감 시각에 함수 호출 | 1만 명 판정을 batch로 나눠 전달 |
| 중복 처리 | 같은 task name으로 중복 예약 방지 | 메시지 재전달 가능성을 멱등 처리로 흡수 |
| 쉬운 비유 | 예약 알람 | 방송 채널 |

## Firestore Security Rules vs IAM

| 구분 | Firestore Security Rules | IAM |
|---|---|---|
| 보호 대상 | 클라이언트의 Firestore 읽기/쓰기 | Google Cloud 리소스 권한 |
| 누가 주로 받나 | 앱 사용자 | service account, 운영자, 함수 |
| 예시 | 본인 player만 read 허용 | Tasks Dispatcher SA만 `endRound` 호출 허용 |
| 헷갈리는 점 | 둘 다 권한이지만 적용 위치가 다르다 | Rules는 앱 데이터 접근, IAM은 인프라 접근 |

## onSnapshot vs polling

| 구분 | onSnapshot | polling |
|---|---|---|
| 방식 | 변경되면 자동으로 알려줌 | 일정 시간마다 다시 읽음 |
| 장점 | 빠르게 반영 | 비용/부하 예측이 쉬움 |
| 단점 | 많은 사람이 같은 문서를 보면 fan-out 발생 | 즉시성은 조금 낮음 |
| 이 프로젝트 | 본인 player 상태 | 공통 game/round 공개 상태 |

## transaction vs idempotency

| 구분 | transaction | idempotency / 멱등성 |
|---|---|---|
| 목적 | 여러 읽기/쓰기를 안전하게 한 번에 처리 | 같은 작업이 여러 번 와도 결과를 한 번처럼 유지 |
| 언제 필요하나 | 입장, phase 전이, batch 상태 갱신 | Cloud Tasks/Pub/Sub 재시도, 중복 호출 |
| 예시 | claims + player + counter를 함께 생성 | `endRound`가 두 번 와도 `adminChoice` 재추첨 금지 |

## dev/prd vs Emulator

| 구분 | Emulator | dev | prd |
|---|---|---|---|
| 위치 | 로컬 | Firebase 개발 프로젝트 | Firebase 운영 프로젝트 |
| 목적 | 빠르고 안전한 테스트 | 실제 클라우드 환경 검증 | 실제 사용자 서비스 |
| 데이터 | 테스트용 | 개발용 | 운영용 |
| 주의 | Cloud Tasks 같은 일부 기능은 우회 어댑터 필요 | prd와 분리 유지 | 실사용자 영향 주의 |

## public data vs private data

| 구분 | 공개 데이터 | 비공개 데이터 |
|---|---|---|
| 누가 보나 | 일반 사용자도 볼 수 있음 | 본인, Admin, Functions 등 제한된 주체 |
| 예시 | `games.winnerNickname`, 라운드 집계 | `clickKey`, `adisonUid`, 지급 개인정보 |
| 목적 | 화면 표시 | 지급, 감사, 보안 검증 |
| 주의 | 공개 문서에는 식별자/개인정보를 넣지 않는다 | 읽기 권한을 강하게 제한한다 |

## task, batch, manifest

| 용어 | 쉬운 뜻 | 관계 |
|---|---|---|
| task | Cloud Tasks에 들어가는 HTTP 호출 작업 | `endRound` 같은 함수 호출을 예약한다. |
| batch | 많은 사용자를 나눈 처리 묶음 | 1만 명을 1000명 단위처럼 나눈다. |
| manifest | batch 목록을 고정한 기록 | 재시도해도 같은 범위를 처리하게 한다. |
