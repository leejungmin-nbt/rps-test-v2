# T17 — 관측·로그·알림

> 함수 로그·메트릭에 환경 라벨을 부여하고, 운영 진단의 1차 신호 (`batches/{i}.status`, `processedBatchCount/expectedBatchCount`, 큐 상태) 를 모니터링 대시보드로 만든다.

## 가이드 정본

- [8. 자동진행 및 서버리스 함수](../guide/08_자동진행_및_서버리스_함수.md) §8.10.4
- [9. 호스팅·배포·환경](../guide/09_호스팅_배포_환경.md) §9.12

## 선행

- [T08](./T08_processBatch.md), [T14](./T14_Cloud_Tasks_PubSub_IAM.md)

## 구현 항목

### 로그 라벨 (9.12.1)

- [ ] 모든 함수 로그에 다음 라벨 부여
  - `env=dev | prd`
  - `function`
  - `gameId`
  - `roundNumber` (해당 시)
  - `batchIndex` (해당 시)
- [ ] 라벨 누락 시 dev 단계에서 빌드 경고

### 모니터링 대시보드 (9.12.3)

- [ ] 환경별 분리된 대시보드 (`env=dev` / `env=prd`)
- [ ] 위젯
  - `processedBatchCount / expectedBatchCount` 비율 (라운드 진행도)
  - Cloud Tasks 큐 길이 + 재시도 횟수
  - 함수 latency (p50/p95/p99) per 함수
  - Firestore read/write 카운트 per 컬렉션
  - `batches/{i}.status == "failed"` 카운트
  - `manifestStatus == "failed"` 카운트
  - `aliveCount` 시계열 (라운드 경계 갱신 가시화)
  - `minInstances` 활성 인스턴스 수 (행사 직전·직후 가시화)

### 알림 라우팅 (9.12.2)

- [ ] dev 5xx 급증 → dev 채널만
- [ ] prd 5xx 급증 → prd 채널 + 운영자 호출 라인
- [ ] dev `batches/{i}.status == "failed"` → dev 채널만
- [ ] prd `batches/{i}.status == "failed"` → prd 채널 + 운영자 호출 라인
- [ ] `manifestStatus == "failed"` 는 prd 에서 즉시 호출 (운영자 수동 복구 필요, 10장)

### 비용 가드 (선택)

- [ ] Firestore read/write 임계값은 placeholder 로 시작 (예: dev 1k 시나리오 관측치의 2배). T18 부하 테스트 결과로 1차 갱신, 11장 비용 가정 확정 시 정본 동기화
- [ ] placeholder 단계에서는 알림 채널을 dev 채널 또는 비활성화로 두고, 임계값이 정본화된 뒤에만 prd 채널 연결

## 산출물

- 로그 라벨링 미들웨어 / 함수 wrapper
- 대시보드 정의 (Cloud Monitoring JSON 또는 Terraform)
- 알림 정책 (Cloud Monitoring alert policy 또는 PagerDuty 연동)

## 완료 조건

- [ ] dev 함수 1회 호출 후 Cloud Logging 에서 `env=dev` 라벨로 필터 가능
- [ ] prd 함수 1회 호출 후 동일 (라벨 분리 확인)
- [ ] 대시보드에서 `processedBatchCount/expectedBatchCount` 가 실시간으로 보임
- [ ] dev 의 의도적 5xx → dev 채널에만 알림
- [ ] prd 의 의도적 batch failed → prd 알림 채널 트리거 (테스트 모드)
