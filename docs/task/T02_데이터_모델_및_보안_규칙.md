## 구현 항목

### 타입 정의 (클라이언트 + 함수 공통)

- [ ] `appState/activeGameId` 타입
- [ ] `games/{gameId}` 타입 (필드 11종, 6.8.2)
- [ ] `games/{gameId}/rounds/{n}` 타입 (`phase` enum 은 `countdown | select | reveal` 만)
- [ ] `games/{gameId}/players/{userId}` 타입 (`status` enum, `aliveShardIndex`, choice 필드)
- [ ] `games/{gameId}/rounds/{n}/batches/{i}` 타입 (`status` 4-state)
- [ ] `games/{gameId}/claims/{adisonUidHash}` 타입
- [ ] `games/{gameId}/counters/alive_{0~9}` 타입
- [ ] `games/{gameId}/result/summary` 타입
- [ ] `games/{gameId}/winnerPrivate/summary` 타입
- [ ] `games.phase` enum: `waiting | countdown | select | reveal | ended` (legacy `open/playing/revealing/finished` 미사용)

### `firestore.rules`

- [ ] 6.10 skeleton 그대로 시작. 모든 도메인 쓰기 `allow create, update, delete: if false`
- [ ] `appState/{docId}` get 만 허용, list 차단
- [ ] `games/{gameId}` 와 `rounds/{n}` get 허용, list 차단 (공개 가능 필드만 저장한다는 전제)
- [ ] `players/{userId}` get: `request.auth.uid == userId || isAdmin()`
- [ ] `claims`, `counters`, `batches`, `result`, `winnerPrivate` read/write Admin only
- [ ] `isAdmin()` 헬퍼는 `request.auth.token.admin == true`
- [ ] Emulator 단위 테스트로 각 권한 매트릭스 6.9 검증

### `firestore.indexes.json`

- [ ] 6장 컬렉션별 계약을 보고 필요한 복합 인덱스 산출 (현재 시점에서는 query 가 거의 없으므로 시작은 minimal)

### 공개 문서 보호

- [ ] `games/{gameId}` 에 6.8.2 금지 필드(`clickKey`, `winnerClickKey`, `adisonUid`, `winnerAdisonUid`, `advertisingId`, 개인정보, `select` 마감 전 `adminChoice`)가 절대 들어가지 않도록 함수 측 dto/serializer 가드 작성

## 산출물

- `shared/types/firestore.ts` (또는 등가 위치) — 컬렉션별 인터페이스
- `firestore.rules`
- `firestore.indexes.json`
- Rules unit test 파일 (`@firebase/rules-unit-testing` 기반)

## 완료 조건

- [ ] Rules unit test 가 6.9 권한 매트릭스의 핵심 분기 (본인/타인/admin/anon × 각 컬렉션 read·write) 를 모두 통과
- [ ] 클라이언트가 `players/{otherUserId}` 를 read 하면 `permission-denied`
- [ ] 클라이언트가 `claims`, `counters`, `batches`, `result`, `winnerPrivate` 어느 것이든 read 하면 `permission-denied`
- [ ] 모든 컬렉션의 Firestore 직접 write 는 `permission-denied` (도메인 쓰기는 함수에서만)
- [ ] 타입 정의가 클라이언트와 함수 양쪽에서 import 가능 (모노레포 공유 또는 동등한 구조)
