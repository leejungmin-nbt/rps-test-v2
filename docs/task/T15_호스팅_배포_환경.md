## 구현 항목

### CDN 헤더 (9.3.2)

- [ ] `index.html` → no-cache 또는 짧은 TTL (구체 값은 13장 위임, 본 태스크는 placeholder `0` 또는 `60s`)
- [ ] 해시 파일명 정적 자산 (`*.[hash].js/css/png` 등) → `Cache-Control: max-age=31536000, immutable`
- [ ] 해시 없는 정적 자산 → 짧은 TTL 또는 ETag 기반 재검증

### SPA rewrite (9.3.3)

- [ ] 모든 경로를 `/index.html` 로 rewrite
- [ ] URL 쿼리 파라미터는 호스팅이 가공하지 않고 통과

### 환경 변수 (9.4.3, 9.8)

- [ ] 클라이언트 빌드 타임 변수: `VITE_FIREBASE_*` 또는 등가 키. `ENV=dev|prd` 로 빌드 분기
- [ ] 함수 runtime: `ENV`, project ID, region, 큐 이름, 함수 URL 자기 환경값
- [ ] Secret Manager 또는 Functions runtime secret 만 비밀 보관. 코드 하드코딩 금지

### 배포 단위 (9.10.1)

- [ ] Hosting 단독 배포 명령
- [ ] Functions 단독 배포 명령
- [ ] Firestore rules / indexes 단독 배포 명령
- [ ] Cloud Tasks 큐 정의 / IAM 변경은 별도 IaC 워크플로 (T14 와 연동)

### 배포 절차 (9.10.2)

- [ ] dev 배포 → Emulator 통합 시나리오 (T16) → prd 배포 순서를 README 또는 `docs/runbook` 에 명시
- [ ] prd 배포 시 rules·IAM 변경은 동료 리뷰 의무 (PR 라벨 또는 GitHub branch protection)

### 롤백 (9.10.3)

- [ ] Hosting 이전 release rollback 절차 문서화
- [ ] Functions 이전 commit 재배포 절차 문서화 (트랜잭션 가드가 멱등성 보장)
- [ ] Rules / IAM 롤백 절차 문서화

### 인앱웹뷰 호환성 (9.11)

- [ ] `index.html` 매 진입 최신 보장
- [ ] URL 파라미터 호스팅 단계 가공 0건 e2e 검증

## 산출물

- `firebase.json` 의 hosting headers / rewrites 정본
- 빌드 스크립트 (`build:dev`, `build:prd`)
- 배포 스크립트 (`deploy:dev:hosting`, `deploy:prd:hosting`, ...)
- `docs/runbook/deploy.md` 같은 절차 문서

## 완료 조건

- [ ] dev 와 prd 의 `index.html` 이 매 진입 최신 응답 (curl 헤더 검증)
- [ ] 해시 정적 자산이 immutable cache header 응답
- [ ] dev 빌드는 dev Firebase config, prd 빌드는 prd config 로 동작 (config 가 코드에 노출되어도 무방한 공개 식별자만)
- [ ] 5단위 배포 명령이 각각 독립적으로 작동
- [ ] 롤백 시뮬레이션 1회 수행 (dev Hosting 이전 release 로 복귀)
- [ ] 인앱웹뷰 시뮬레이션 (Chrome devtools 모바일 + 인앱 UA) 으로 5종 파라미터가 SPA 까지 통과

## 위임 / 미결정

- `index.html` TTL 구체값 / cleanUrls / trailingSlash → 13장
- Custom domain → 13장
- CI/CD 자동화 → 13장
