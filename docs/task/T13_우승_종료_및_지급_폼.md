# T13 — 우승 / 종료 화면 + 우승자 지급 폼

> `phase == "ended"` 분기에서 우승자에게는 개인정보 폼을, 그 외 사용자에게는 결과 화면을, 이월 시에는 안내 화면을 보여준다.

## 구현 항목

### 우승자 식별

- [ ] 본인 `userId` 와 `result/summary.winnerId` 비교는 클라이언트에서 직접 하지 않는다 (`result/summary` 는 일반 read 차단, 6.9)
- [ ] 우승 후보 판단은 **결정적 단일 신호** 로 한다: `games/{gameId}.phase == "ended"` AND `games/{gameId}.endedReason == "winner"` AND 본인 `games/{gameId}/players/{userId}.status == "alive"`. 정의상 `ended` 시점에 `status == "alive"` 인 본인 player 가 있으면 우승자, 없으면 비우승자다 (6.8.4)
- [ ] `winnerNickname` 일치 여부는 폼 노출 게이트로 사용하지 않는다. 닉네임은 unique 보장이 없으므로 (T04) 충돌 시 비우승자에게 폼이 노출될 수 있다. `winnerNickname` 은 화면 표시용으로만 사용
- [ ] 우승자 폼 진입의 최종 권위는 `submitWinnerInfo` 호출 결과다. 서버가 `result/summary.winnerId == request.auth.uid` 로 검증한다 (8.6.6)

### 우승 화면 (winner)

- [ ] `games.winnerNickname` 표시 (공개 가능)
- [ ] 본인이 우승자이면 개인정보 폼 안내
- [ ] 폼 필드: 실명 (`name`), 연락처 (`phone`), 주소 (`address?`)
- [ ] 동의 체크박스 2종: 개인정보 수집 (`privacyConsentAt` 필수), 제3자 제공 (`thirdPartyConsentAt?`)
- [ ] 제출 시 `submitWinnerInfo` Callable 호출
  - 성공 → "지급 안내가 곧 전달됩니다" 안내 (수동 지급은 운영자 업무)
  - `failed-precondition` (우승자 아님) → "우승자가 아닙니다" 안내 후 일반 종료 화면
  - `already-exists` → "이미 제출되었습니다" 안내
  - `invalid-argument` → 폼 재입력 안내

### 일반 종료 화면 (winner 가 아닌 사용자)

- [ ] `winnerNickname` 표시 + "다음 회차에 다시 도전해보세요" 안내
- [ ] 라운드별 이력 요약 (선택은 본인 player 문서에 저장된 것만)

### 이월 화면 (`endedReason == "carryover"`)

- [ ] "이번 회차는 우승자가 없어 다음 회차로 이월됩니다"
- [ ] 이월 누적 정책은 13장 미정이므로 문구는 placeholder 유지

## 산출물

- `WinnerFormView`, `WinnerAnnounceView`, `CarryoverView` 컴포넌트
- 폼 검증 + `submitWinnerInfo` 호출 어댑터

## 완료 조건

- [ ] `phase == "ended"` AND `endedReason == "winner"` → 우승 화면
- [ ] 우승자 본인이 정상 폼 제출 시 `winnerPrivate/summary` 생성 (Emulator 로 확인)
- [ ] 동의 미체크 시 클라이언트 검증 차단, 실수로 호출되어도 서버 `invalid-argument`
- [ ] 같은 우승자가 두 번 제출 시 `already-exists` 안내
- [ ] `endedReason == "carryover"` 시 이월 화면

## 위임 / 미결정

- 이월 누적 정책 → 13장
- 제세공과금 22% 처리 → 13장
- 동의 문구 최종 → 13장
- 운영자 수동 지급 절차 → 10장
