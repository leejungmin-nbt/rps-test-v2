# T06 — 라운드 페이즈 엔진 (`startRound` / `beginSelect`)

> `waiting → countdown → select` 까지의 페이즈 전이를 트랜잭션 가드로 구현하고, Cloud Tasks 에 `beginSelect` / `endRound` 를 결정적 task name 으로 예약한다.

## 가이드 정본

- [3. 게임 룰 및 라운드 흐름](../guide/03_게임_룰_및_라운드_흐름.md) §3.2, §3.3
- [8. 자동진행 및 서버리스 함수](../guide/08_자동진행_및_서버리스_함수.md) §8.5 (전이 #1, #2, #4), §8.6.3, §8.7
- [9. 호스팅·배포·환경](../guide/09_호스팅_배포_환경.md) §9.7 (task ID 산출)

## 선행

- [T05](./T05_submitChoice.md)
- [T14](./T14_Cloud_Tasks_PubSub_IAM.md) 는 stub 가능. 본 태스크는 **검증 단계 클라이언트 트리거 모드 (8.3.2)** 만 먼저 완성한다. OIDC 검증과 실제 Cloud Tasks 큐 연동은 T14 완료 후 합친다. 트랜잭션 가드는 두 모드에서 동일하므로 합류 시 가드 코드는 변경하지 않는다

## 구현 항목

### `startRound` (전이 #1, #4)

- [ ] 호출 주체: 운영자 트리거 (첫 라운드) 또는 batch 완료 finalizer 의 결정적 enqueue (전이 #4)
- [ ] 가드 (전이 #1): `phase == "waiting"` AND (`now() >= closesAt` 또는 운영자 강제 시작)
- [ ] 가드 (전이 #4): `processedBatchCount == expectedBatchCount` AND `survivorsAfter >= 2`
- [ ] 같은 트랜잭션에서 갱신:
  - 전이 #1: `phase = "countdown"`, `currentRound = 1`, `rounds/1` create (`phase = "countdown"`, `startedAt`, `selectStartsAt`), `totalPlayers` 고정
  - 전이 #4: `phase = "countdown"`, `currentRound = n+1`, `rounds/{n+1}` create
- [ ] 외부 효과: Cloud Tasks 에 `beginSelect-{gameId}-{n}` 예약 (`schedule_time = rounds/{n}.selectStartsAt`)

### `beginSelect` (전이 #2)

- [ ] HTTP 함수, Cloud Tasks OIDC 토큰 검증 (`serviceAccountEmail` + `audience` 두 축)
- [ ] 가드: `phase == "countdown"` AND `currentRound == n` AND `now() >= rounds/{n}.selectStartsAt`
- [ ] 같은 트랜잭션에서: `phase = "select"`, `rounds/{n}.phase = "select"`, `roundEndsAt`, `rounds/{n}.endsAt`
- [ ] 외부 효과: Cloud Tasks 에 `endRound-{gameId}-{n}` 예약
- [ ] 가드 불일치 시 `200 + no-op`

### task ID 산출 (9.7.2)

- [ ] 논리 키: `{kind}-{gameId}-{roundNumber}`
- [ ] 실제 task ID: `{kind}-{sha256(gameId).slice(0, 8)}-{roundNumber}` 형태
- [ ] NFC + 소문자화, 비허용 문자 `_` 치환
- [ ] 동일 조합 중복 createTask → `ALREADY_EXISTS` 자연 거부

### `aliveCount` 보정 (전이 #1 시점)

- [ ] 전이 #1 경계에서 10개 샤드 합산해 `games.aliveCount` 보정, `games.totalPlayers` 한 번 고정 (8.5.2)
- [ ] 전이 #4 자체에서는 합산 반복하지 않고 직전 라운드 종료 보정값 사용

### 검증 단계 분기

- [ ] 환경 변수 한 줄로 클라이언트 트리거 + 결정적 task name 멱등 가드 모드 지원 (8.3.2)
- [ ] 운영 단계와 트랜잭션 가드 동작 동일
- [ ] T14 stub 마감 조건: (i) OIDC 검증 bypass 분기가 `ENV == dev | emulator` 일 때만 활성화, (ii) `ENV != dev|emulator` 빌드에서 stub 분기가 dead code 임을 정적 분석 또는 빌드 시 검증 (T16 9.9.2 와 동일 가드)

## 산출물

- `functions/src/startRound.ts`, `functions/src/beginSelect.ts`
- task ID 산출 유틸 (`shared/taskId.ts`) — 본 태스크가 정본 작성 책임. T14 는 이 유틸을 사용만 한다
- 단위 테스트 (가드 통과 / 가드 불일치 / 중복 호출 멱등성)
- 통합 테스트 (Emulator 에서 전이 #1 → #2 흐름)

## 완료 조건

- [ ] `phase != "waiting"` 에서 `startRound` 호출 시 no-op
- [ ] `phase == "waiting"` AND `now() >= closesAt` 에서 호출 시 `phase = "countdown"`, `currentRound = 1`, `rounds/1` 생성
- [ ] Cloud Tasks task `beginSelect-{hashPrefix}-1` 이 `selectStartsAt` 에 예약됨
- [ ] `beginSelect` 가 OIDC 검증 실패 시 401
- [ ] 같은 task ID 로 두 번 createTask 시 두 번째는 `ALREADY_EXISTS`
- [ ] 전이 #1 경계에서 `aliveCount`, `totalPlayers` 가 샤드 합산값으로 set 됨

## 위임 / 미결정

- `aliveCount` 보정 주체 (전환 함수 직접 vs 별도 집계 함수) → 13장
- `minInstances` 활성화 절차·구체값 → 10장 (절차) / 11장 (값)
