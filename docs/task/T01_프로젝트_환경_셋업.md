# T01 — 프로젝트 / 환경 초기 셋업

> Firebase 프로젝트와 코드 저장소를 dev / prd 두 환경에서 동작 가능한 상태로 만든다. 이 태스크가 끝나면 빈 SPA 한 화면을 두 환경에 각각 배포할 수 있다.

## 가이드 정본

- [1. 프로젝트 개요](../guide/01_프로젝트_개요.md) §1.3, §1.6
- [9. 호스팅·배포·환경](../guide/09_호스팅_배포_환경.md) §9.3, §9.4, §9.5

## 선행

없음.

## 구현 항목

- [ ] React + Vite SPA 스캐폴딩 (SSR 미사용). Next.js SPA 모드 등 다른 번들러로 변경하려면 13장에 등록한 뒤 결정
- [ ] Cloud Functions 코드 디렉터리(예: `functions/`) 초기화. runtime 은 Functions 가 지원하는 LTS Node
- [ ] Firebase 프로젝트 2개 생성 (dev / prd) — 9.4.2 의 4축 격리 원칙
- [ ] region `asia-northeast3` 고정
- [ ] `firebase.json` 항목을 9.5 정본에 맞게 작성
  - hosting: `public`, `ignore`, `rewrites` (모든 경로 → `/index.html`), `headers` 3계층
  - functions: `source`, `runtime`, `region`
  - firestore: `rules`, `indexes`
  - emulators: auth / firestore / functions / pubsub / hosting / ui 활성화
- [ ] Blaze 요금제 활성화 확인
- [ ] 환경 식별 변수 `ENV=dev | prd` 를 클라이언트 빌드와 함수 runtime 양쪽에 주입
- [ ] `.env.example` 커밋 + 비밀은 Secret Manager / runtime secret 만 사용 (9.8)
- [ ] 로컬 빌드와 dev 배포가 한 번 성공하는 것을 확인

## 산출물

- `firebase.json`, `.firebaserc` (dev/prd alias)
- React 빌드 산출물 (`dist/index.html` 한 페이지)
- 빈 Functions index 파일 (실제 함수는 후속 태스크에서 추가)
- `.env.example`, 환경별 `.env.dev.local` / `.env.prd.local` (비커밋)

## 완료 조건

- [ ] `firebase deploy --project dev --only hosting` 성공, dev URL 에서 빈 SPA 렌더 확인
- [ ] `firebase deploy --project prd --only hosting` 성공, prd URL 에서 빈 SPA 렌더 확인
- [ ] dev 와 prd 의 Firebase 프로젝트 ID 가 다름을 `firebase use` 출력으로 확인
- [ ] Emulator UI 가 로컬에서 정상 기동 (`firebase emulators:start`)
- [ ] 코드 안에 service account key, secret 이 하드코딩되어 있지 않음

## 위임 / 미결정

- dev/prd 두 프로젝트 채택 여부 자체는 13장 PM 결정 대기. 본 태스크는 9장 권장안인 옵션 (b) 를 전제로 진행한다.
- Custom domain, CI/CD 자동화, `index.html` 캐시 TTL 구체값은 13장에서 별도 결정.
