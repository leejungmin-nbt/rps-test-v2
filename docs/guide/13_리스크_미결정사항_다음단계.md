# 13. 리스크·미결정사항·다음 단계

> PM·운영·기술 결정이 필요한 항목을 한곳에 모아두는 문서다. 현재는 상세 설계보다 **결정 큐 관리**에 집중한다.

---

## 13.1 PM 결정 대기

| 항목 | 결정 필요 내용 | 영향 |
|---|---|---|
| 제세공과금 22% | 자사 부담 / 당첨자 부담 / 기타 처리 방식 | 지급 안내, 운영 매뉴얼 |
| 이월 정책 | 100만원 유지 / 누적 / 별도 정책 | 종료 화면 문구, PM 커뮤니케이션 |
| 행사 일정 | 월 4회 기준 요일·시각 | 운영 절차, `minInstances`, 알림 |
| 운영 정원 N | 5천 / 1만 / 1.5만 등 | 정원 게이트, 부하 테스트 |
| 라운드 수·선택 시간 | 총 라운드 수, 라운드당 선택 제한 | UX, 총 게임 시간, 비용 |

---

## 13.2 기술 결정 대기

| 항목 | 현재 기준 | 결정 필요 내용 |
|---|---|---|
| dev/prd 분리 | 9장은 dev+prd 2프로젝트를 권장 | 최종 채택 여부 |
| `index.html` 캐시 TTL | no-cache 또는 짧은 TTL | 0초 / 60초 / 300초 등 |
| CI/CD | 수동 배포 가능 | GitHub Actions 등 자동화 도입 여부 |
| custom domain | Firebase 기본 도메인 가능 | 운영 도메인 필요 여부 |
| `adminChoiceHash` | 미도입 | hash-then-reveal 투명성 강화 여부 |
| 선택 변경 | 현재는 라운드 중 1회 제출 기준 | 마감 전 변경 허용 여부 |
| `aliveCount` 보정 주체 | 보정 시점만 확정 | 전환 함수 내부 / 별도 집계 함수 |
| TTL/데이터 보존 | 미정 | 보존 기간, 삭제 주체, 감사 정책 |
| App Check | 검증 단계에서는 보류 | 운영 전 reCAPTCHA v3 등 도입 여부 |
| BigQuery Export | 검증 단계에서는 보류 | 어뷰징 사후 분석용 export 여부 |

## 13.3 지금은 미뤄도 되는 항목

검증 단계 규모가 작다면 다음은 운영 직전에 처리해도 된다.

- 분산 샤드 정원 게이트의 고도화
- Cloud Tasks 정밀 자동 진행
- 1만 동접 부하 테스트
- App Check / BigQuery Export
- 운영자 상세 매뉴얼
- 비용 확정 시뮬레이션

## 13.4 다음 단계

1. PM 결정 대기 항목을 먼저 확정한다.
2. 운영 정원 N이 정해지면 12장 부하 테스트 계획을 상세화한다.
3. Cloud Tasks 운영 모드 전환 시 10장 운영 절차와 11장 비용 추정을 확장한다.
4. 실제 운영 전 리허설 결과를 각 장에 반영한다.
