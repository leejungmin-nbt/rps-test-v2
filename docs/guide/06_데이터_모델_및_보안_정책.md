# 6. 데이터 모델 및 보안 정책

> 가위바위보 챌린지의 Firestore 데이터가 어디에 저장되고, 어떤 정보가 공개 가능하며, 어떤 쓰기는 반드시 서버를 통과해야 하는지 정의한다.
>
> - **다루는 것** — Firestore 경로, 주요 필드, 공개/비공개 데이터 경계, 읽기/쓰기 권한, 보안 규칙 방향
> - **위임하는 것** — 정원 게이트와 재진입 알고리즘, Cloud Tasks/Pub/Sub 구현, 운영자 지급 업무, 미결정 정책
> - **상위 문서** — 게임 흐름은 [3. 게임 룰 및 라운드 흐름](./03_게임_룰_및_라운드_흐름.md), 서비스 구조와 단일 쓰기 원칙은 [4. 시스템 아키텍처](./04_시스템_아키텍처.md), 사용자 식별 흐름은 [5. 사용자 식별 및 인증](./05_사용자_식별_및_인증.md)을 따른다

## 6.1 한 화면 요약

이 장에서 반드시 지키는 규칙은 다음과 같다.

### 공개 데이터 경계

- **공개 문서는 허용 필드 whitelist 로만 설계한다.** Firestore 는 문서 read 를 허용하면 문서 안의 모든 필드가 노출되므로, 공개 문서에는 공개 가능한 필드만 저장한다.
- **`games/{gameId}` 는 공개 상태 문서지만 외부 지급 식별자와 개인정보를 절대 두지 않는다.** `winnerClickKey`, `winnerAdisonUid`, `advertisingId`, 연락처, 주소 같은 값은 공개 문서 금지 필드다.
- **관전 화면은 공개 집계만 사용한다.** `games.aliveCount`, 현재 `phase`, `games/{gameId}/rounds/{n}` 의 라운드 집계처럼 개인을 특정하지 않는 값만 사용한다.

### 읽기/쓰기 권한

- **모든 도메인 쓰기는 서버 함수 단일 게이트웨이를 통과한다.** 클라이언트는 Firestore 문서를 직접 create/update/delete 하지 않는다.
- **본인 참가자 상태만 제한적으로 읽는다.** 사용자는 자기 `games/{gameId}/players/{userId}` 문서만 읽을 수 있고, 다른 플레이어 문서나 전체 `games/{gameId}/players` 목록은 읽지 않는다.

### 식별과 상태

- **중복 참여 차단 기준은 `clickKey` 가 아니라 `adisonUid` 다.** URL `uid` 를 정규화·해시한 `adisonUidHash` 로 `games/{gameId}/claims/{adisonUidHash}` 를 선점한다.
- **`adminChoice` 는 `select` 마감 전 저장/노출하지 않는다.** 라운드 종료 전 애디슨 손이 공개되면 선택 조작 위험이 생긴다.
- **상태 필드는 guide 용어를 따른다.** 게임/라운드 흐름은 `waiting → countdown → select → reveal → ended` 로 설명하고, 이전 초안의 `open`, `playing`, `revealing`, `finished` 는 legacy 매핑으로만 다룬다.

## 6.2 이 문서의 기준과 용어 정본

이 문서는 guide 시리즈 안에서 데이터 모델과 보안 정책의 기준 문서 역할을 한다. 1~5장에서 이미 정의한 프로젝트 범위, 게임 흐름, 아키텍처, 사용자 식별 정책을 이어받아 Firestore 경로·필드·권한을 이 장에서 고정한다.

따라서 이후 문서나 구현에서 데이터 경로, 공개/비공개 경계, 상태 필드 이름을 다룰 때는 이 장의 용어를 기준으로 삼는다.

### 정본 용어

| 개념 | 이 guide 에서 쓰는 정본 |
|---|---|
| 게임/라운드 진행 단계 | `phase` |
| 게임 공통 진행 필드 | `games.phase` |
| 라운드 진행 필드 | `games/{gameId}/rounds/{roundNumber}.phase` |
| 플레이어 생존 상태 | `games/{gameId}/players/{userId}.status` = `alive` / `eliminated` |
| 배치 처리 상태 | `games/{gameId}/rounds/{n}/batches/{i}.status` |
| URL `uid` | `adisonUid` |
| URL `click_key` | `clickKey` |

> 기존 문서의 `games.status: open/playing/revealing/finished` 는 과거 초안의 상태명이다. 이 문서에서는 guide 흐름과 맞추기 위해 `games.phase` / `rounds.phase` 를 기준으로 쓴다.

## 6.3 이 문서의 범위와 비범위

### 이 문서에서 정의하는 것

| 항목 | 이 장의 책임 |
|---|---|
| Firestore 경로 | 어떤 문서/컬렉션에 어떤 종류의 데이터를 두는지 정의 |
| 주요 필드 | 구현자가 혼동하지 않아야 할 핵심 필드와 공개 가능 여부 정의 |
| 민감도 계층 | public / private own-read / restricted server-admin-only 구분 |
| 읽기/쓰기 권한 | 클라이언트 read 범위와 write 차단 원칙 정의 |
| 보안 규칙 방향 | 배포 rules 의 골격과 금지 원칙 정의 |
| 관전 데이터 계약 | 관전 화면에서 읽어도 되는 데이터 범위 정의 |

### 다른 장으로 위임하는 것

| 항목 | 위임 대상 |
|---|---|
| 정원 게이트, 분산 admission counter, 재진입·이탈 정책 | 작성 예정: 7장 동시성·정원·중복참여 정책 |
| Cloud Tasks, Pub/Sub, `startRound`/`endRound`/`processBatch` 내부 구현 | 작성 예정: 8장 자동진행 및 서버리스 함수 |
| 운영자 지급 절차, 어드민 업무, 감사 기록 | 작성 예정: 10장 운영 정책 및 관리자 업무 |
| TTL 기간, 선택 변경 허용 여부, `adminChoiceHash` 도입 여부 | 작성 예정: 13장 리스크·미결정사항·다음 단계 |
| 비용 수치와 부하 테스트 방식 | 작성 예정: 11장 비용 추정, 12장 부하테스트 및 검증 계획 |

## 6.4 데이터/보안 설계 원칙

| 원칙 | 설명 |
|---|---|
| 클라이언트 신뢰 금지 | 클라이언트가 보낸 라운드 번호, 마감 시각, UID, 선택값은 그대로 믿지 않고 서버에서 재검증한다 |
| 단일 서버 쓰기 게이트웨이 | 입장, 선택 제출, 라운드 전환, 우승자 확정, 지급 상태 변경은 Cloud Functions/Admin 경로에서만 수행한다 |
| 공개/비공개/제한 영역 분리 | 공개 문서에는 집계·상태만 두고, 개인 식별자·지급 식별자·개인정보는 private 또는 restricted 영역으로 분리한다 |
| 본인 상태만 실시간 구독 | 사용자는 자기 `games/{gameId}/players/{userId}` 만 `onSnapshot` 한다. 공통 상태는 5초 내외 폴링 전략을 따른다 |
| 라운드별 대량 초기화 금지 | 매 라운드 1만 명의 선택값을 `null` 로 초기화하지 않고, `choiceRound` 로 현재 라운드 선택인지 판별한다 |
| 결과 선공개 방지 | `adminChoice` 는 `select` 마감 전 공개 문서에 저장하지 않는다 |
| 공통 상태 원자 갱신 | `games.phase`, `games.currentRound`, 현재 라운드 포인터는 같은 트랜잭션에서 갱신해 클라이언트가 엇갈린 라운드를 읽지 않게 한다 |
| Admin 식별 | 클라이언트 기반 관리자 화면이 필요하면 Firebase Auth custom claims 의 `admin == true` 로 식별한다 |

## 6.5 전체 Firestore 경로 맵

민감도 계층은 다음 세 단계로 나눈다.

| 계층 | 의미 | 예시 |
|---|---|---|
| **Public allowed-fields** | 문서 read 가 공개될 수 있으므로 공개 가능한 필드만 저장 | `games/{gameId}`, `games/{gameId}/rounds/{n}`, `appState/activeGameId` |
| **Private own-read** | 본인만 읽을 수 있는 참가자 상태. public 은 아니지만 클라이언트 본인에게는 내려갈 수 있음 | `games/{gameId}/players/{userId}` |
| **Restricted server/admin-only** | 일반 클라이언트 read/write 금지. 서버 함수 또는 관리자만 접근 | `games/{gameId}/claims`, `games/{gameId}/counters`, `games/{gameId}/rounds/{n}/batches`, `games/{gameId}/result/summary`, `games/{gameId}/winnerPrivate/summary` |

### Public allowed-fields 경로

| 경로 | 역할 | 읽는 주체 | 쓰는 주체 |
|---|---|---|---|
| `appState/activeGameId` | 현재 활성 게임 포인터 | 누구나 get | Admin |
| `games/{gameId}` | 게임 공통 상태와 공개 가능한 결과 | 누구나 get | Functions/Admin |
| `games/{gameId}/rounds/{roundNumber}` | 라운드 상태와 공개 집계 | 누구나 get | Functions/Admin |

### Private own-read 경로

| 경로 | 역할 | 읽는 주체 | 쓰는 주체 |
|---|---|---|---|
| `games/{gameId}/players/{userId}` | 참가자 본인 상태와 입장 식별 정보 | 본인 + Admin/Functions | Callable Function |

### Restricted server/admin-only 경로

| 경로 | 역할 | 읽는 주체 | 쓰는 주체 |
|---|---|---|---|
| `games/{gameId}/rounds/{n}/batches/{i}` | 배치 처리 상태와 멱등성 기록 | Admin/Functions | Functions |
| `games/{gameId}/claims/{adisonUidHash}` | 중복 참여 방지용 선점 문서 | Admin/Functions | Functions (`joinGame`) |
| `games/{gameId}/counters/alive_{0~9}` | 생존자 수 분산 카운터 | Admin/Functions | Functions |
| `games/{gameId}/result/summary` | 우승 결과와 지급 확인 정보 | Admin/Functions | Functions/Admin |
| `games/{gameId}/winnerPrivate/summary` | 우승자 개인정보 수령 정보 | Admin/Functions | Functions (`submitWinnerInfo`) |

> Public allowed-fields 문서는 Firestore read 를 허용하면 전체 문서 필드가 노출된다. 따라서 “공개 가능한 필드만 저장한다”가 보안 정책의 핵심이다.

## 6.6 URL 파라미터와 내부 식별자 매핑

광고 참여 후 NBT 오퍼월 인앱웹뷰는 이벤트 페이지에 URL 쿼리 파라미터 5종을 붙여 진입시킨다. 클라이언트는 이 값을 `joinGame` 호출 payload 로 전달하고, 서버는 다시 정규화·검증한다.

### 파라미터 의미와 공개 정책

| URL 파라미터 | 내부 필드 | 주 용도 | 공개 정책 |
|---|---|---|---|
| `uid` | `adisonUid` | Adison 사용자 식별, 중복 참여 차단 기준 | public 금지 |
| `advertising_id` | `advertisingId` | 사용자 구분 보조값 | public 금지 |
| `click_key` | `clickKey` | 수동 지급 확인용 외부 키 | public 금지 |
| `pub_code` | `pubCode` | 진입 매체사 구분 | 공개 문서에 둘 경우 집계/표시 목적만 별도 검토 |
| `pub_app_code` | `pubAppCode` | 진입 매체사 앱 구분 | 공개 문서에 둘 경우 집계/표시 목적만 별도 검토 |

### 저장 위치

| 내부 필드 | 저장 위치 |
|---|---|
| `adisonUid` | `games/{gameId}/players/{userId}` private own-read, `games/{gameId}/claims/{adisonUidHash}` 문서 ID/`adisonUidHash` restricted |
| `advertisingId` | `games/{gameId}/players/{userId}` private own-read, 우승 시 `games/{gameId}/result/summary` restricted |
| `clickKey` | `games/{gameId}/players/{userId}` private own-read, 우승 시 `games/{gameId}/result/summary.winnerClickKey` restricted |
| `pubCode` | `games/{gameId}/players/{userId}` private own-read, 우승 시 `games/{gameId}/result/summary` restricted |
| `pubAppCode` | `games/{gameId}/players/{userId}` private own-read, 우승 시 `games/{gameId}/result/summary` restricted |

### 중복 참여 기준

- 중복 참여 차단 키는 `clickKey` 가 아니라 **`adisonUid`** 다.
- `clickKey` 는 같은 사용자라도 클릭마다 바뀔 수 있어 중복 차단 기준으로 부적합하다.
- 서버는 `adisonUid` 를 정규화한 뒤 `adisonUidHash = sha256(normalize(adisonUid))` 를 만들고, `games/{gameId}/claims/{adisonUidHash}` 를 선점한다.
- 원본 `adisonUid`, `advertisingId`, `clickKey` 는 public 문서에 저장하지 않는다.

### private own-read 에 원본 URL 파라미터를 두는 이유와 한계

현재 계약은 `games/{gameId}/players/{userId}` 에 원본 URL 파라미터 5종을 저장할 수 있게 둔다. 이 문서는 본인만 읽을 수 있으므로 public 은 아니며, 운영·디버깅·우승자 확인 흐름과 기존 데이터 모델의 정합성을 유지하기 위한 선택이다.

다만 보안 강도를 더 높이고 싶다면, 장기적으로 원본 `clickKey` / `adisonUid` / `advertisingId` 를 별도 restricted 문서로 옮기고 `games/{gameId}/players/{userId}` 에는 hash 또는 표시용 최소 필드만 남기는 방안을 13장 미결정사항에서 검토한다.

## 6.7 phase/status 매핑 정책

guide 03장의 사용자-facing 흐름은 다음과 같다.

```txt
waiting → countdown → select → reveal → ended
```

최종 guide 계약에서는 게임/라운드 진행 단계에 `phase` 라는 이름을 사용한다.

| Guide phase | 데이터 모델 표현 | 의미 | 주요 공개 필드 |
|---|---|---|---|
| `waiting` | `games.phase` | 게임 시작 전 입장 대기 또는 입장 가능 구간 | `currentRound`, `closesAt`, `totalPlayers` 캐시 |
| `countdown` | `games.phase`, `games/{gameId}/rounds/{n}.phase` | 라운드 선택 시작 전 카운트다운 | `currentRound`, `games/{gameId}/rounds/{n}.startedAt`, `games/{gameId}/rounds/{n}.endsAt` |
| `select` | `games.phase`, `games/{gameId}/rounds/{n}.phase` | 생존자가 선택을 제출하는 구간 | `roundEndsAt`, `survivorsBefore` |
| `reveal` | `games.phase`, `games/{gameId}/rounds/{n}.phase` | 선택 마감 후 애디슨 손 공개와 판정 결과 노출 | `adminChoice`, `survivorsAfter`, `eliminatedCount`, 선택 분포 집계 |
| `ended` | `games.phase` | 우승 또는 이월로 게임 종료 | `winnerNickname`, `finishedAt`, `endedReason` |

허용 전이는 다음 흐름을 기본으로 한다. 예외 전이나 재시도 멱등성 처리는 작성 예정 8장에서 다룬다.

```txt
games.phase: waiting → countdown → select → reveal → countdown/select ... → ended
games/{gameId}/rounds/{n}.phase: countdown → select → reveal
```

`games/{gameId}/rounds/{n}.phase` 는 개별 라운드 안의 진행 상태만 표현하므로 `waiting` 을 사용하지 않는다. 라운드가 끝났다는 사실은 `reveal` 단계의 결과 필드(`revealedAt`, `survivorsAfter`, `eliminatedCount`)가 채워진 상태로 표현하고, 게임 전체 종료는 `games.phase = "ended"` 로 표현한다.

### legacy status 매핑

기존 상세 모델 일부는 `games.status` 또는 `rounds.status` 에 다음 값을 사용한다. 새 guide 문서에서는 아래 표를 legacy 참고로만 사용한다.

| 기존 표현 | guide 기준 해석 | 처리 방향 |
|---|---|---|
| `open` | `waiting` 중 입장 가능 상태 | 필요하면 `admissionOpen: boolean` 또는 `closesAt` 으로 보조 표현 |
| `playing` | `select` | `phase: "select"` 로 통일 |
| `revealing` | `reveal` | `phase: "reveal"` 로 통일 |
| `finished` | `ended` | `phase: "ended"` 로 통일 |

`games/{gameId}/players/{userId}.status` 는 생존 여부(`alive` / `eliminated`)를 뜻하므로 `phase` 로 바꾸지 않는다. `games/{gameId}/rounds/{n}/batches/{i}.status` 도 배치 처리 상태(`pending` / `processing` / `done` / `failed`)이므로 그대로 `status` 를 사용한다. 기존 상태명을 발견하면 새 `phase` enum 으로 마이그레이션하고, 새 문서·코드에는 legacy enum 을 추가하지 않는다.

## 6.8 주요 컬렉션별 계약

### 6.8.1 `appState/activeGameId`

현재 활성 게임을 찾기 위한 루트 포인터 문서다.

| 필드 | 타입 | 공개 여부 | 설명 |
|---|---|---|---|
| `gameId` | string | 공개 가능 | 현재 활성 게임 ID |
| `updatedAt` | timestamp | 공개 가능 | 포인터 갱신 시각 |

#### 권한 정책

- read: 누구나 get 가능
- write: Admin 만
- list: 불필요하면 차단

---

### 6.8.2 `games/{gameId}`

게임 한 회차의 공개 가능한 공통 상태만 담는다.

| 필드 | 타입 | 공개 여부 | 설명 |
|---|---|---|---|
| `phase` | string enum | 공개 가능 | `waiting` / `countdown` / `select` / `reveal` / `ended` |
| `currentRound` | number | 공개 가능 | 현재 라운드 번호. 시작 전은 `0` |
| `closesAt` | timestamp | 공개 가능 | 입장 마감 시각 |
| `roundEndsAt` | timestamp \| null | 공개 가능 | 현재 선택 페이즈 마감 시각 |
| `totalPlayers` | number | 공개 가능 | 누적 참가자 수 표시용 캐시 |
| `aliveCount` | number | 공개 가능 | 생존자 수 표시용 캐시 |
| `winnerNickname` | string \| null | 공개 가능 | 우승 확정 후 1명에 한해 공개하는 표시용 닉네임 |
| `endedReason` | string \| null | 공개 가능 | `winner` / `carryover` 등 종료 사유 |
| `finishedAt` | timestamp \| null | 공개 가능 | 게임 종료 시각 |
| `updatedAt` | timestamp | 공개 가능 | 마지막 서버 갱신 시각 |

#### `games/{gameId}` 금지 필드

- `clickKey`, `winnerClickKey`
- `adisonUid`, `winnerAdisonUid`
- `advertisingId`, `winnerAdvertisingId`
- `pubCode`, `winnerPubCode` 등 지급/정산 확인용 원본 식별자
- `winnerId` 같은 내부 식별자 원본. 공개 화면에는 `winnerNickname` 처럼 공개 표시용 필드만 둔다
- 이름, 전화번호, 주소 등 경품 수령 개인정보
- 라운드 종료 전 `adminChoice`

> `games/{gameId}` 는 공개 read 대상이므로, 보안 규칙으로 필드 일부만 숨긴다는 가정은 하지 않는다. 숨겨야 하는 값은 이 문서에 저장하지 않는다.

#### 상태 갱신 계약

- `games.phase` 와 `games.currentRound` 는 같은 트랜잭션에서 갱신한다. 예를 들어 `countdown` 으로 전이할 때 클라이언트가 이미 새 라운드 번호를 기준으로 `games/{gameId}/rounds/{currentRound}` 를 읽을 수 있어야 한다.
- 공개 문서는 다수 사용자가 주기적으로 읽으므로, 새 공개 필드를 추가할 때는 관전/공통 상태 폴링 응답 크기와 공개 가능성을 함께 검토한다.

---

### 6.8.3 `games/{gameId}/rounds/{roundNumber}`

라운드별 진행 상태와 공개 가능한 결과 집계를 담는다.

| 필드 | 타입 | 공개 여부 | 설명 |
|---|---|---|---|
| `phase` | string enum | 공개 가능 | `countdown` / `select` / `reveal`. `waiting` 과 `ended` 는 게임 단위 `games.phase` 에서만 사용 |
| `startedAt` | timestamp | 공개 가능 | 라운드 카운트다운 시작 기준 시각 |
| `selectStartsAt` | timestamp | 공개 가능 | 카운트다운 종료 및 선택 시작 예정 시각 |
| `endsAt` | timestamp | 공개 가능 | 선택 마감 예정 시각 |
| `adminChoice` | string \| null | `reveal` 이후 공개 | 애디슨 손. `select` 마감 전에는 저장하지 않거나 `null` 유지 |
| `revealedAt` | timestamp \| null | 공개 가능 | 애디슨 손 공개 시각 |
| `survivorsBefore` | number \| null | 공개 가능 | 라운드 시작 전 생존자 수 |
| `survivorsAfter` | number \| null | 공개 가능 | 라운드 종료 후 생존자 수 |
| `eliminatedCount` | number \| null | 공개 가능 | 해당 라운드 탈락자 수 |
| `choiceDistribution` | map \| null | 공개 가능 | 가위/바위/보 선택 분포 집계. 개인 선택값은 포함하지 않음 |
| `manifestStatus` | string enum | 공개 필요성 낮음 | batch manifest 상태. `building` / `ready` / `failed` |
| `expectedBatchCount` | number | 공개 필요성 낮음 | 운영/처리 상태 표시가 필요할 때만 공개 검토 |
| `processedBatchCount` | number | 공개 필요성 낮음 | 운영/처리 상태 표시가 필요할 때만 공개 검토 |

#### 주의사항

- `games/{gameId}/rounds/{n}.phase` 값은 `countdown` / `select` / `reveal` 로 제한한다. `ended` 는 게임 단위 `games.phase` 에서만 사용한다.
- `selectStartsAt` 은 `beginSelect` 가드의 기준 시각이다. `startedAt` 은 카운트다운 시작, `endsAt` 은 선택 마감 의미로 구분한다.
- `adminChoice` 는 `select` 마감 전 공개 문서에 저장하지 않는다.
- 개별 사용자의 선택값, Firebase Auth UID, `adisonUid`, 닉네임 목록은 `rounds` 에 저장하지 않는다.
- 관전 화면은 이 문서의 집계 필드만 사용한다.

참가자 1인의 상태 문서다. 문서 ID는 Firebase Anonymous Auth UID 를 사용한다.

| `adisonUidHash` | string | 본인 + Admin/Functions | `claims` 문서 ID와 같은 해시 |
| `aliveShardIndex` | number | 본인 + Admin/Functions | 입장 시 결정된 `counters/alive_{0~9}` 샤드 인덱스. 탈락 차감 대칭성 보장용 |
| `advertisingId` | string \| null | 본인 + Admin/Functions | URL `advertising_id` |
| `pubCode` | string | 본인 + Admin/Functions | URL `pub_code` |
| `pubAppCode` | string | 본인 + Admin/Functions | URL `pub_app_code` |
| `status` | string enum | 본인 + Admin/Functions | `alive` / `eliminated` |
| `eliminatedRound` | number \| null | 본인 + Admin/Functions | 탈락 라운드 |
| `choice` | string \| null | 본인 + Admin/Functions | 마지막 제출 선택값 |
| `choiceRound` | number \| null | 본인 + Admin/Functions | `choice` 가 제출된 라운드 번호 |
| `choiceSubmittedAt` | timestamp \| null | 본인 + Admin/Functions | 선택 제출 시각 |
| `joinedAt` | timestamp | 본인 + Admin/Functions | 입장 시각 |
| `lastProcessedRound` | number | Admin/Functions 중심 | 마지막 판정 반영 라운드. 멱등성 보조 |

#### 권한 정책

- 본인은 자기 문서만 get/onSnapshot 할 수 있다.
- 다른 플레이어 문서는 읽을 수 없다.
- 전체 `games/{gameId}/players` list/query 는 클라이언트에 허용하지 않는다.
- 클라이언트 직접 create/update/delete 는 금지한다. `joinGame`, `submitChoice`, `processBatch` 같은 서버 함수가 갱신한다.

### 6.8.5 `games/{gameId}/rounds/{n}/batches/{i}`

라운드 종료 시 대량 참가자 판정을 나눠 처리하기 위한 배치 상태 문서다.

| 필드 | 타입 | 공개 여부 | 설명 |
|---|---|---|---|
| `batchIndex` | number | Restricted | 배치 번호 |
| `status` | string enum | Restricted | `pending` / `processing` / `done` / `failed` |
| `processedCount` | number | Restricted | 처리한 플레이어 수 |
| `eliminatedCount` | number | Restricted | 탈락 처리 수 |
| `survivorCount` | number | Restricted | 배치 내 생존자 수 |
| `startAfterUid` | string \| null | Restricted | UID 커서 시작점 |
| `endAtUid` | string \| null | Restricted | UID 커서 종료점 |
| `limit` | number | Restricted | batch 최대 처리 수. 기본 1000 |
| `startedAt` | timestamp | Restricted | 처리 시작 시각 |
| `finishedAt` | timestamp \| null | Restricted | 처리 종료 시각 |
| `errorMessage` | string \| null | Restricted | 실패 시 진단 메시지 |

#### 권한/처리 정책

- 일반 클라이언트 read/write 금지
- Pub/Sub 재시도에 대비한 멱등성 기록으로 사용
- 멱등성 단위는 경로의 `(roundNumber, batchIndex)` 조합, 즉 `games/{gameId}/rounds/{n}/batches/{i}` 문서 하나다
- `startedAt` 은 `processing` lease 판단에도 사용한다
- 처리 알고리즘은 작성 예정 8장으로 위임

### 6.8.6 `games/{gameId}/claims/{adisonUidHash}`

Adison `uid` 기반 중복 참여를 원자적으로 차단하기 위한 선점 문서다.

| 필드 | 타입 | 공개 여부 | 설명 |
|---|---|---|---|
| `userId` | string | Restricted | 선점한 Firebase Auth UID |
| `adisonUidHash` | string | Restricted | 문서 ID와 같은 해시 |
| `clickKeyHash` | string | Restricted | 동일 `click_key` 재사용·이상치 추적을 위한 운영 모니터링용 해시 |
| `pubCode` | string | Restricted | 진입 매체 코드 |

## 6.10 Firestore Rules 작성 방향

Firestore Rules 는 도메인 검증을 담당하지 않는다. 도메인 검증은 서버 함수에서 처리하고, Rules 는 클라이언트 직접 쓰기와 민감 데이터 접근을 차단하는 방어선으로 둔다.

아래는 방향을 보여주는 skeleton 이며, 배포 전에는 실제 필드명·인덱스·관리자 도구 요구사항에 맞춰 별도 검증해야 한다.

<details>
<summary>Firestore Rules skeleton</summary>

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() {
      return request.auth != null;
    }

    function isAdmin() {
      return signedIn() && request.auth.token.admin == true;
    }

    match /appState/{docId} {
      allow get: if docId == "activeGameId";
      allow list: if false;
      allow create, update, delete: if docId == "activeGameId" && isAdmin();
    }

    match /games/{gameId} {
      // 공개 문서는 공개 가능한 필드만 저장한다는 전제 아래 get 허용.
      allow get: if true;
      allow list: if false;
      allow create, update, delete: if false;

      match /players/{userId} {
        allow get: if signedIn() && (request.auth.uid == userId || isAdmin());
        allow list: if false;
        allow create, update, delete: if false;
      }

      match /rounds/{roundId} {
        // 라운드 문서도 공개 가능한 필드만 저장한다는 전제 아래 get 허용.
        allow get: if true;
        allow list: if false;
        allow create, update, delete: if false;

        match /batches/{batchId} {
          allow read, write: if isAdmin();
        }
      }

      match /claims/{claimId} {
        allow read, write: if isAdmin();
      }

      match /counters/{counterId} {
        allow read, write: if isAdmin();
      }

      match /result/{docId} {
        allow read, write: if isAdmin();
      }

      match /winnerPrivate/{docId} {
        allow read, write: if isAdmin();
      }
    }
  }
}
```

</details>

실제 Cloud Functions Admin SDK 는 보안 규칙을 통과하지 않고 서버 권한으로 Firestore 를 갱신한다. 따라서 클라이언트가 수행해야 하는 도메인 변경은 Firestore 직접 write 가 아니라 Callable Function 호출로 표현한다.

## 6.11 서버 쓰기 게이트웨이와 데이터 영향

6장은 함수 내부 알고리즘을 다루지 않고, 각 서버 함수가 어떤 데이터 영역에 영향을 주는지만 정의한다.

### 함수 영향 요약

| 함수 | 호출 주체 | 주요 read 대상 | 주요 write 대상 |
|---|---|---|---|
| `joinGame` | 클라이언트 Callable | `games/{gameId}`, `games/{gameId}/claims/{adisonUidHash}` 존재 여부, `games/{gameId}/players/{userId}` | `games/{gameId}/claims/{adisonUidHash}`, `games/{gameId}/players/{userId}`, `games/{gameId}/counters/alive_*` |
| `submitChoice` | 클라이언트 Callable | `games/{gameId}`, `games/{gameId}/players/{userId}` | `games/{gameId}/players/{userId}.choice`, `games/{gameId}/players/{userId}.choiceRound`, `games/{gameId}/players/{userId}.choiceSubmittedAt` |
| `startRound` | Admin/서버 또는 내부 enqueue | `games/{gameId}`, `games/{gameId}/counters/alive_*` | `games/{gameId}.phase`, `games/{gameId}.currentRound`, `games/{gameId}/rounds/{n}.startedAt`, `games/{gameId}/rounds/{n}.selectStartsAt` |
| `beginSelect` | Cloud Tasks HTTP | `games/{gameId}`, `games/{gameId}/rounds/{n}` | `games/{gameId}.phase`, `games/{gameId}.roundEndsAt`, `games/{gameId}/rounds/{n}.phase`, `games/{gameId}/rounds/{n}.endsAt` |
| `endRound` | Cloud Tasks HTTP | `games/{gameId}`, `games/{gameId}/rounds/{n}` | `games/{gameId}.phase`, `games/{gameId}/rounds/{n}.adminChoice`, `games/{gameId}/rounds/{n}.manifestStatus`, `games/{gameId}/rounds/{n}/batches/{i}` |
| `processBatch` | Pub/Sub | `games/{gameId}/players/{userId}`, `games/{gameId}/rounds/{n}`, `games/{gameId}/rounds/{n}/batches/{i}` | `games/{gameId}/players/{userId}`, `games/{gameId}/rounds/{n}/batches/{i}`, `games/{gameId}/counters/alive_*`, 라운드 집계 필드 |
| `submitWinnerInfo` | 클라이언트 Callable | `games/{gameId}` | `games/{gameId}/winnerPrivate/summary` |

### 함수별 계약

| 함수 | 이 장에서의 계약 |
|---|---|
| `joinGame` | 인증, URL 파라미터 검증, 중복 선점, 참가자 생성, 입장 시 `aliveShardIndex` 저장, 카운터 갱신은 서버에서만 수행 |
| `submitChoice` | 본인·생존·현재 라운드·마감 전 여부 검증 후 선택 필드 갱신 |
| `startRound` | `waiting/reveal → countdown` 전이, 라운드 문서의 `startedAt`/`selectStartsAt` 생성, `beginSelect` 예약, 공개 카운터 캐시 보정 |
| `beginSelect` | `countdown → select` 전이, 선택 마감 시각(`roundEndsAt`, `rounds/{n}.endsAt`) 설정, `endRound` 예약 |
| `endRound` | `reveal` 전이, `adminChoice` 결정/공개, `manifestStatus` 와 batch manifest 고정, 배치 처리 dispatch |
| `processBatch` | 승패 판정, 탈락 처리, 저장된 `aliveShardIndex` 기준 카운터 차감, 배치/플레이어 멱등성 기록 |
| `submitWinnerInfo` | 우승자 본인 여부와 1회 제출을 검증한 뒤 개인정보 저장 |

함수의 payload, 트랜잭션 순서, 재시도 정책, Cloud Tasks 큐 설정은 작성 예정 8장에서 다룬다.

## 6.12 관전 모드 공개 데이터 계약

관전 모드는 탈락자 또는 외부 사용자가 라운드 흐름을 볼 수 있게 하되, 개별 참가자 정보를 노출하지 않는다.

### 관전 화면에서 사용할 수 있는 정보

| 데이터 | 출처 | 비고 |
|---|---|---|
| 현재 phase | `games.phase` | 공개 가능 |
| 현재 라운드 번호 | `games.currentRound` | 공개 가능 |
| 현재 생존자 수 | `games.aliveCount` | 샤드 합산 결과 캐시 |
| 라운드 시작/마감 시각 | `games/{gameId}/rounds/{n}.startedAt`, `games/{gameId}/rounds/{n}.endsAt` | 공개 가능 |
| 애디슨 손 | `games/{gameId}/rounds/{n}.adminChoice` | `reveal` 이후만 공개 |
| 라운드 생존/탈락 집계 | `games/{gameId}/rounds/{n}.survivorsBefore`, `survivorsAfter`, `eliminatedCount` | 공개 가능 |
| 선택 분포 집계 | `games/{gameId}/rounds/{n}.choiceDistribution` | 개인 선택값 없이 집계만 공개 |
| 공개 우승자 닉네임 | `games.winnerNickname` | 우승 확정 후 1명에 한해 공개하는 표시명만. 우승자 내부 UID 는 공개하지 않는다 |

### 관전 화면에서 금지하는 정보

- 전체 `games/{gameId}/players` 목록
- 개별 플레이어의 `choice`
- 개별 플레이어의 `adisonUid`, `advertisingId`, `clickKey`
- 우승자의 `winnerClickKey`, `winnerAdisonUid`, `winnerAdvertisingId`
- 경품 수령 개인정보
- `select` 마감 전 `adminChoice`

## 6.13 확정 사항과 미결정 사항

### 확정 사항

- URL 쿼리 파라미터 5종은 `uid`, `advertising_id`, `click_key`, `pub_code`, `pub_app_code` 다.
- URL `uid` 는 문서 내에서 `adisonUid` 로 부르고, Firebase Auth UID 와 구분한다.
- 중복 참여 기준은 `adisonUid` 기반 `adisonUidHash` 다.
- `clickKey` 는 지급 확인용이지 중복 참여 차단 키가 아니다.
- 공개 문서에는 공개 가능한 필드만 저장한다.
- `games.phase` 는 `waiting` / `countdown` / `select` / `reveal` / `ended` 를 사용한다.
- `games/{gameId}/rounds/{n}.phase` 는 `countdown` / `select` / `reveal` 만 사용한다.
- `games/{gameId}/players/{userId}.status` 는 생존 상태, `games/{gameId}/rounds/{n}/batches/{i}.status` 는 배치 처리 상태로 유지한다.
- `games/{gameId}/players/{userId}.aliveShardIndex` 는 입장 시 결정된 생존자 카운터 샤드 인덱스이며, 탈락 차감은 이 값을 기준으로 한다.
- 모든 도메인 쓰기는 Callable Function 또는 서버 내부 함수가 수행한다.
- `adminChoice` 는 `select` 마감 전 공개 문서에 저장하지 않는다.

### 미결정 사항

| 항목 | 결정 필요 내용 | 위임 |
|---|---|---|
| `games/{gameId}/result/summary` 우승자 본인 read | 우승자 본인 확인 페이지가 필요한지, 필요 시 어떤 필드만 노출할지 | 작성 예정: 13장 |
| TTL 보존 기간 | `games/{gameId}/players`, `games/{gameId}/claims`, `games/{gameId}/rounds`, `winnerPrivate` 보관/삭제 기간 | 작성 예정: 13장 |
| `adminChoiceHash` | 투명성 강화를 위해 hash-then-reveal 을 도입할지 | 작성 예정: 13장 또는 8장 |
| 라운드 중 선택 변경 | 최초 제출만 인정할지, 마감 전 변경을 허용할지 | 작성 예정: 13장 |
| 운영자 검색 인덱스 | `games/{gameId}/players` 에서 `clickKey` / `adisonUid` / `nickname` 검색 인덱스 필요 여부 | 작성 예정: 10장 |
| URL 원본값 분리 | `games/{gameId}/players/{userId}` 에 raw URL 파라미터를 계속 둘지, restricted secret 문서로 분리할지 | 작성 예정: 13장 |
| list 권한 | 공개 round history list 가 필요한지, get-only 로 충분한지 | 작성 예정: 10장/13장 |
