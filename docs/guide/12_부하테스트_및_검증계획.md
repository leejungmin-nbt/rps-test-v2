# 12. 부하테스트 및 검증 계획

> 운영 전 성능·안정성 검증을 위한 문서다. 현재는 테스트 범위를 보존하는 **경량 스텁**으로 둔다.

---

## 12.1 현재 상태

- MVP/검증 단계에서는 소규모 기능 안정성 확인을 우선한다.
- 1만 동접 기준의 부하 테스트는 운영 전 단계에서 수행한다.
- 도구는 아직 확정하지 않는다. 후보는 k6 또는 Artillery다.

---

## 12.2 운영 전 검증 범위

| 구분 | 검증 내용 |
|---|---|
| 단계 부하 | 1k → 5k → 1만 순서로 상승 |
| 입장 처리 | 정원 게이트, 중복 참여, `claims` 선점 |
| 라운드 처리 | 선택 제출, 미제출 탈락, 라운드 전환 지연 |
| batch 처리 | Pub/Sub fan-out, batch 실패/재시도, 집계 정합성 |
| 비용 측정 | Firestore/Functions/Tasks 사용량과 11장 비용 가정 비교 |
| 인앱웹뷰 | NBT 오퍼월 webview 진입, 쿼리 파라미터 유지, 캐시 이슈 |

---

## 12.3 작성 트리거

- 운영 정원 N이 확정된다.
- Cloud Tasks / Pub/Sub 운영 모드가 구현된다.
- 정원 게이트와 분산 샤드 카운터가 구현된다.
- 실제 매체사 인앱웹뷰에서 QA를 진행한다.
