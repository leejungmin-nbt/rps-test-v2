# 3. 게임 룰 및 라운드 흐름

> 가위바위보 챌린지의 게임 룰과 라운드가 어떻게 진행되는지를 정의한다.
>
> - **다루는 것** — 페이즈 상태 머신, 라운드 생애 주기, 종료 분기, 예외 경로
> - **위임하는 것** — 데이터 모델, 자동 진행 메커니즘, 동시성 정책, 관전 구독 전략 (각 전담 챕터로)
> - **상위 문서** — 프로젝트 배경과 범위는 [1. 프로젝트 개요](./01_프로젝트_개요.md) 를 따른다

## 3.2 게임 룰과 페이즈 상태 머신

게임 룰은 다음과 같다.

- **애디슨 vs 유저** 구도의 가위바위보 토너먼트.
- 애디슨에게 **이긴 사람만 다음 라운드 진출**, **비기거나 진 사람은 탈락**.
- 선택 마감까지 제출하지 않은 생존자는 **미제출자로 간주해 탈락**.
- **최후 1인** 이 남을 때까지 진행. 전원 탈락 시 다음 회차로 이월.

라운드는 다음 페이즈 시퀀스를 따라 진행된다.

```
waiting → countdown → select → reveal → 다음 라운드 / ended
```

각 페이즈의 책임은 다음과 같다.

| 페이즈 | 목적 | 유저 가능 액션 | 시스템 동작 | 전이 조건 |
|---|---|---|---|---|
| **waiting** | 게임 시작 전 대기. 이 페이즈 안에서 입장이 수락되며, 첫 `countdown` 시작과 동시에 입장이 마감된다 | 이벤트 페이지 진입, 입장 신청 | 정원 미달이면 입장 수락, 정원 초과 시 차단 | 운영자 또는 자동 트리거가 첫 라운드를 시작하면 `countdown` |
| **countdown** | 다음 라운드 시작 직전 짧은 카운트다운 | 화면 대기 (입력 없음) | 카운트다운 시각이 끝나면 `select` 로 전이 | 카운트다운 종료 |
| **select** | 라운드 입력 페이즈. 정해진 시간 동안 가위·바위·보 중 하나를 제출 | 가위/바위/보 선택 제출 (1회) | 마감 시각까지 입력 수신, 마감 후 추가 제출 차단. 마감까지 제출하지 않은 생존자는 미제출자로 표시 | 마감 시각 도달 |
| **reveal** | 애디슨 손 공개와 일괄 판정 | 화면 대기 | **마감 직후 서버가 무작위로 애디슨 손을 결정**하고 공개한다. 이긴 사람만 생존하고, 비기거나 진 사람과 미제출자는 탈락 처리한다. 라운드 단위 집계(생존 확률, 가위/바위/보 분포) 산출. 비고: **애디슨 손은 글로벌(모든 유저 공통) · 사전 미결정 · `select` 마감 전 비공개** | 결과 확인 구간을 거쳐 분기 |
| **다음 라운드 / ended** | 분기 처리 | 진출자는 다음 `countdown` 으로, 탈락자는 관전 모드 화면으로, 우승 확정 또는 전원 탈락 시 결과 화면으로 | 생존자가 1명이면 **우승 확정 후 `ended`**, 0명이면 **이월 처리 후 `ended`**, 2명 이상이면 다음 `countdown` 예약 | 다음 라운드 시작 또는 게임 종료 |

## 3.3 라운드 흐름

한 라운드의 생애 주기를 시간 순으로 풀어 쓰면 다음과 같다.

1. **입장 수락 구간 (`waiting`)** — 게임이 시작되기 전, 정원에 도달하지 않은 동안 신규 유저의 입장을 수락한다. 첫 `countdown` 이 시작되는 순간 입장이 마감되고, 이후엔 새 유저가 들어오지 못한다. 정원 게이트의 동시성 처리 방식은 7장에서 다룬다.
2. **카운트다운 (`countdown`)** — 라운드 시작 직전의 짧은 대기 구간. 유저는 입력하지 않는다. 카운트다운 시간이 0이 되면 즉시 `select` 페이즈로 전이된다.
3. **선택 (`select`)** — 정해진 선택 시간 동안 유저가 가위·바위·보 중 하나를 제출한다. 1회 제출만 허용되며, 마감 시각이 지나면 추가 제출이 차단된다. 마감 시각까지 제출하지 않은 생존자는 미제출자로 간주한다.
4. **공개와 판정 (`reveal`)** — `select` 마감 직후 서버가 가위·바위·보 중 하나를 무작위로 골라 애디슨의 손을 결정하고 모든 유저에게 공개한다. 같은 라운드의 모든 유저는 같은 애디슨 손을 보고, 그 손과 자신의 손을 비교해 이긴 사람만 생존하고 비기거나 진 사람은 탈락으로 판정된다. 미제출자는 애디슨 손과 무관하게 해당 라운드에서 탈락한다. 동시에 라운드 단위 집계(생존자 수, 생존 확률, 가위/바위/보 분포) 가 산출돼 화면에 노출된다.
5. **결과 확인 구간** — `reveal` 직후 다음 `countdown` 이 시작되기 전까지의 짧은 대기 구간. 유저는 본인 결과와 라운드 집계를 확인한다. 이 구간이 끝나면 분기로 진입한다.
6. **분기** — 생존자가 1명이면 **우승 확정 후 `ended`**, 0명이면 **이월 처리 후 `ended`**, 2명 이상이면 다음 라운드의 `countdown` 으로 진입한다.

참가자와 관전자가 보는 화면은 다르다 — 생존자는 본인 선택과 라운드 집계, 탈락자는 관전 모드에서 라운드 집계 위주의 정보를 본다. 관전 모드에서 어떤 데이터를 어떻게 구독하는지(클라이언트 구독 전략·fan-out 비용)는 4장에서, 관전 모드가 노출 가능한 데이터 모델 범위는 6장에서 다룬다.

## 3.4 종료 조건과 결과 처리

게임은 다음 두 분기에서 끝난다.

- **우승 (최후 1인)** — 마지막 라운드의 `reveal` 후 생존자가 정확히 1명이면 우승자로 확정한다. 우승자 식별자는 자동 기록되고, 1등 경품은 운영자가 수동 적립한다.
- **이월 (전원 탈락)** — `reveal` 결과 생존자가 0명이면 그 회차는 우승자 없이 종료되고, 다음 회차로 이월된다. 이월의 구체적 의미(경품 누적 방식 등)는 PM 합의 미정 항목이다.

두 경우 모두 `ended` 페이즈로 전이된다. `ended` 이후의 신규 진입과 재호출 처리 정책은 7장에서 다룬다.

## 3.5 예외 경로와 위임

라운드 흐름 위에서 발생할 수 있는 예외 상황과, 각각의 처리 책임을 어느 챕터가 맡는지 정리한다.

| 상황 | 처리 방향 | 위임 챕터 |
|---|---|---|
| 미제출자(타임아웃) 처리 | 선택 마감까지 제출하지 않은 생존자는 해당 라운드에서 탈락 처리 | 3장 |
| 게임 진행 중 같은 유저가 재호출하거나 페이지를 떠남 | 자동 탈락·재진입 차단 정책 (구현 기준 정책 / PM 재확인 필요) | 7장 |
| 자동 진행 트리거(시각 도달 시 페이즈 전이) | 클라이언트 트리거 + 멱등성 또는 운영 단계 정밀 자동화 | 8장 |
| `reveal` 전 애디슨 손이 사전 노출되는 부정행위 | 비공개 저장·공개 시점 제어 등 보안 규칙 상세 | 6장 |
| 관전 모드에 노출 가능한 데이터 모델 범위 | 노출 가능 필드·접근 권한 | 6장 |
| 관전 모드 클라이언트 구독 전략과 fan-out 비용 | 폴링 vs 실시간 구독, 비용 영향 | 4장 |
| 라운드 수·라운드당 선택 시간·카운트다운 길이·결과 확인 구간 길이 | 운영 파라미터 미확정 | 13장 |

이 표에 없는 항목 중 **새로 발생하는 룰·정책 결정**은 본 문서가 아니라 13장에 미결정사항으로 등록한 뒤 PM 합의를 거친다.
