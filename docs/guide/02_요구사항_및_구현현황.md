# 2. 요구사항 및 구현 현황

> 이 문서는 가위바위보 챌린지 MVP의 요구사항, 현재 구현 현황, 운영 전 남은 조치를 한눈에 보기 위한 **현황 대시보드**다. 세부 배경과 범위는 [1. 프로젝트 개요](./01_프로젝트_개요.md)를 따른다.

---

## 2.1 이 문서의 역할

- **목적**: PM·개발·운영자가 요구사항별 현재 상태와 다음 조치를 빠르게 파악할 수 있게 한다.
- **범위**: 요구사항, 구현 상태, 운영 전 조치, PM 결정 대기 항목만 다룬다.
- **제외**: 상세 아키텍처, Firestore 스키마, 보안 규칙, 자동화 구현 세부는 이 문서에 복제하지 않는다.
- **작성 기준**: 이 문서는 독립적으로 읽히는 최종 guide 문서다.

---

## 2.5 용어 footnote

- 광고 참여 후 이벤트 페이지로 이동할 때 `uid`, `advertising_id`, `click_key`, `pub_code`, `pub_app_code` 5종 파라미터를 전달한다.
- `uid`, `advertising_id`는 사용자 구분에 사용한다. 본문에서는 URL `uid`와 Firebase Auth UID를 구분하기 위해 URL `uid`를 `adisonUid`로 풀어쓴다.
- `click_key`는 수동 지급 확인에 사용한다. 기존 `paramA`는 최신 기준에서 `click_key`를 의미하며, 코드 필드명으로는 `clickKey`가 쓰일 수 있다.
- `pub_code`, `pub_app_code`는 진입 매체사 구분에 사용한다.
- Firebase Auth UID는 `userId`로 표기하고, Firestore `players/{userId}` 문서 ID와 연결한다.
- 중복 참여/입장 선점 기준은 `click_key`가 아니라 Adison `uid`이며, 선점 문서는 `claims/{adisonUidHash}`다.
- 상세 필드, 권한, 보안 규칙, 동시성 정책은 예정 문서 `06_데이터_모델_및_보안_정책.md`, `07_동시성_정원_중복참여_정책.md`에서 다룬다.
